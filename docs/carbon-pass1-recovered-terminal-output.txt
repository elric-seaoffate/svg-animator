  and Strips Stage 8–15 Image/Layer Fields

  • Files & Lines: app.js:7346-7348, internal/web/static/js/engine-bridge.js:1173-1242, 1530-1685, 2038-2383,
  pkg/engine/scene/scene.go:696-709, 805-839, 990-992

  • Reproducible Call Path:
      1. Upload background photo (setLoadedPhoto → EngineBridge.setBackground sets s.background in Go) → render() runs at app.
      js:7347 → EngineBridge.syncScene() → Scene.SetState → SetFromSnapshot sets s.background = nil (scene.go:708).
      2. Crop background (applyCrop → EngineBridge.cropBackground) → WASM Background.Crop returns {success: false, error: "no

  Date.now() overwrites Go's monotonic revision).
  • Root Cause: render() unconditionally pushes JS state into Go via normalizeSceneSnapshot, which was never updated completely
  for Stages 8–15.
  • Impact: Go Background.* commands are 100% non-functional after the first render; foreground image crops/clips are silently
  destroyed whenever syncFromEngineSnapshot runs.
  • Confidence: Confirmed.
  • Smallest Safe Remediation: Include full background, images (with data, crop, cropVersions, activeCropVersionId, clip, visible,
  locked, metadata), object visible/locked/opacity/metadata, flow custom*, layer visible/locked, and ?? instead of || for numeric

  ## K. Security and Robustness

  ### 1. Local Single-User Assumptions vs Network-Exposed Reality

  • Although SVG Animator Studio is designed as a self-hosted studio, it binds 0.0.0.0:8088 by default (main.go:37,
  config.json:2)—meaning it is network-exposed to the LAN/container network out of the box AND reachable from any malicious web
  page in the user's browser via cross-origin CSRF / DNS rebinding (P1-018).

  ### 2. Confirmed Reachable Vulnerabilities (Ordered by Severity)

  1. Arbitrary Local File Read (file:// LFI) & SSRF (P1-004, CRITICAL): POST /api/export → file://<tmpDir>/index.html with
  unsanitized svgMarkup + --no-sandbox + --allow-file-access-from-files.
  2. Stored DOM/SVG/CSS XSS (P1-005, CRITICAL): Unescaped IDs, colors, and data URIs in .sva / SQLite schema_json execute
  arbitrary JS in the studio (which can then invoke /api/export or exfiltrate all SQLite projects) and in exported .html/.svg
  files.
  3. .sva Zip-Bomb Memory Exhaustion (P1-016, HIGH): Spoofed UncompressedSize64 headers bypass sva.Validate and allocate up to
  1000 × 100 MiB in sva.Decode.
  4. Cross-Origin CSRF + Unbounded Chromium/FFmpeg Process Spawning + .m3u8 FFmpeg Input (P1-018, HIGH): Unauthenticated endpoints
  with no Origin check, no dimension/FPS/duration ceiling, no concurrency semaphore, no ReadHeaderTimeout, and no audio extension
  allowlist.
  5. XML/HTML Template Injection in CLI/Generator (internal/generator/generator.go:131-185, MEDIUM): Unescaped fmt.Sprintf
  interpolation of title, mimeType, FrameMouldingData, and effect strings.

  ## M. Stage 16 Readiness Assessment

  Stage 16 plans external effect-control runtime bindings (telemetry/API-driven node states, flow rates, glow pulses, ripple
  triggers, camera/optics control) and portable standalone web widgets without bundling the Go/WASM editor runtime.

  ### Blocking Architectural Gaps Before Stage 16

  1. Unscoped Global SVG <defs> & CSS Selectors (P1-023 — Hard Blocker for Multi-Widget Pages): Two widgets mounted inline on one
  dashboard will collide on #viewportClip, #opt-focus, #ts-mask, #nodeDropShadow, #flowPath-1, #glowGrad-1, #rippleMask-1, .
  camera-rig, and @keyframes camKenBurns.
  2. Non-Uniform Addressing & Flat Editor-DOM Control Schema: Nodes/Flows/Glows/Ripples use bare integer IDs (1, 2), Images/Groups
  use prefixed strings (image-1, group-1), and Camera/Optics/Frame have no object IDs at all (stored as 96 HTML input IDs like
  startXZoomSlider). Exported <g> elements carry data-node-id etc., but do not export data-sva-name or a structured widget binding
  manifest mapping user-assigned names (Node.Name, Flow.Name) to targetable properties.
  3. Split SMIL vs Runtime Animation Control (P1-020): Standalone SVGs rely on static SMIL attributes (dur, repeatCount, values)
  with zero JS controller hooks, whereas TimelinePlayer requires EngineBridge and still ignores Flows/Glows/Ripples/Nodes.
  4. Split State Authority (P1-001, P1-002, P1-007): Defining external binding schemas in Stage 16 while JS and Go hold diverging
  schemas (syncScene stripping metadata!) would cause metadata-stored telemetry bindings on Nodes/Flows/Glows/Ripples/Images to be
  wiped on every render()!

  ### Concrete Stage 16 Preparation Blueprint

  1. Repair P1-001 / P1-007 first so Metadata on all scene objects survives syncScene and *.Update intact.
  2. Add deterministic instancePrefix scoping to all SVG <defs> IDs, url(#...) references, and CSS classes/@keyframes.
  3. Emit semantic data-sva-type, data-sva-id, and data-sva-name attributes plus an optional <script type="application/json"
  class="sva-bindings"> descriptor block inside widget exports.
  4. Build a small, zero-WASM, instance-scoped SVAWidget.mount(el, opts) runtime (destroy()-clean) that patches scoped
  SVG/CSS/SMIL attributes directly.
